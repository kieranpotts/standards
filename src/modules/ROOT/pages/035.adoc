This technical standard provides guidelines for writing Python code that is clear, maintainable, and consistent.
It is based on {link-pep8}[PEP 8], the language's own style guide, and
{link-google-pyguide}[Google's Python Style Guide], supplemented with the
typing-related PEPs and current community tooling conventions. Other sources are listed in the references section
at the end of this document.

== References

* Van Rossum, G, Warsaw, B, and Coghlan, N (2001).
  {link-pep8}[_PEP 8: Style Guide for Python Code_].
  — The language's own official style guide, and the primary source for this standard's formatting, whitespace,
  and naming conventions.

* Goodger, D and Van Rossum, G (2001).
  {link-pep257}[_PEP 257: Docstring Conventions_].
  — The source for this standard's docstring structure and placement rules.

* Google.
  {link-google-pyguide}[_Google Python Style Guide_].
  — The source for the 88-character line length, `TODO` comment format, and Google-style docstring sections used
  in this standard.

* Van Rossum, G, Lehtosalo, J, and Langa, Ł (2014).
  {link-pep484}[_PEP 484: Type Hints_].
  — Introduces the type hint syntax this standard requires on public interfaces.

* Levkivskyi, I, Roach, S, Van Rossum, G, and Lehtosalo, J (2017).
  {link-pep526}[_PEP 526: Syntax for Variable Annotations_].
  — Extends type hints to variable declarations.

* Solomatin, E (2019).
  {link-pep585}[_PEP 585: Type Hinting Generics In Standard Collections_].
  — The source for preferring builtin generic syntax (`list[int]`) over the deprecated `typing` aliases.

* Cannon, B (2018).
  {link-pep563}[_PEP 563: Postponed Evaluation of Annotations_].
  — The source for the `from __future__ import annotations` recommendation in
  <<Deferred evaluation of annotations>>.

* Moss, A and Elliott, C (2019).
  {link-pep604}[_PEP 604: Allow writing union types as X | Y_].
  — The source for the `X | None` union syntax preferred in <<Type hints>>.

* Python Software Foundation.
  {link-python-tutorial}[_The Python Tutorial_].
  — The official introductory reference for the language.

* Astral.
  {link-ruff}[_Ruff_].
  — The linter and formatter recommended in <<Linting, formatting, and type checking>>.

* Astral.
  {link-uv}[_uv_].
  — The package and environment manager recommended in <<Virtual environments>>.

* Python Software Foundation.
  {link-python-src-layout}[_src layout vs flat layout_].
  — The source for the package layout guidance in <<Package layout>>.
