= TS-17: Graphical user interfaces (GUIs)
:toc: macro
:toc-title: Contents

This technical standard covers the design and implementation of graphical user interfaces (GUIs):
interfaces composed of windows, views, and on-screen controls, operated by pointer, touch, or keyboard. The guidance
is platform-agnostic, and applies to desktop applications, mobile applications, and web front-ends alike.

This is a deliberately thin standard. The usability principles that apply to every kind of human-computer interface —
feedback, cognitive load, error messages, visual perception, typography — are covered by
xref:015.adoc[*TS-15: User interfaces*], and are not repeated here. What follows is limited to the concerns that are
specific to graphical interfaces: platform conventions, layout, controls and input, interface states, error recovery,
and accessibility.

For the web-specific implementation of these requirements — including the detailed treatment of WCAG conformance,
performance, and responsive design — see xref:018.adoc[*TS-18: Web GUIs*]. For text-based interfaces, see
xref:016.adoc[*TS-16: Command line interfaces (CLIs)*].

== References

* ISO (2020). https://www.iso.org/standard/75258.html[_ISO 9241-110:2020: Ergonomics of human-system interaction —
  Part 110: Interaction principles_]. — The platform-independent reference for interaction design. Its seven
  principles (suitability for the user's tasks, self-descriptiveness, conformity with user expectations,
  learnability, controllability, use error robustness, and user engagement) underpin <<Platform conventions>>,
  <<Error prevention and recovery>>, and the explicit-state requirement in <<States and feedback>>.

* W3C (2023). https://www.w3.org/TR/WCAG22/[_Web Content Accessibility Guidelines (WCAG) 2.2_]. — The source for the
  Level AA baseline in <<Accessibility>>: contrast ratios, the 24×24 pixel minimum target size (SC 2.5.8) cited in
  <<Input modalities>>, focus visibility, and the reduced-motion and flash thresholds.

* W3C (n.d.). https://www.w3.org/WAI/ARIA/apg/practices/keyboard-interface/[_Developing a Keyboard Interface_]. ARIA
  Authoring Practices Guide. — The source for the keyboard model in <<Keyboard operability>>: the distinction between
  the tab sequence and arrow-key navigation within composite components, focus visibility and persistence, and focus
  restoration on dialog dismissal.

* Nielsen Norman Group (2020). https://www.nngroup.com/articles/confirmation-dialog/[_Confirmation Dialogs Can
  Prevent User Errors_]. — The source for <<Undo in preference to confirmation>>: reserving dialogs for serious
  consequences, labeling buttons with the actions they perform, avoiding default answers, requiring non-standard
  gestures for dangerous operations, and the primacy of undo over confirmation.

* Nielsen Norman Group (2019). https://www.nngroup.com/articles/proximity-consequential-options/[_Dangerous UX:
  Consequential Options Close to Benign Options_]. — The source for the separation of destructive and benign actions
  in <<Error prevention and recovery>>, and the target-spacing guidance in <<Input modalities>>.
