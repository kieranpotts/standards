= References

* Learn JSON Schema (n.d.). https://www.learnjsonschema.com/2020-12/[_2020-12 keyword reference_]. — The source for the
  Validation, Applicator, Core, Unevaluated, Meta-Data (Annotations), and Content vocabulary keyword definitions in
  <<validation-keywords,Validation keywords>>, <<applicator-keywords,Applicator keywords>>, <<schema-identification,Schema identification>>, <<unevaluated-keywords,Unevaluated keywords>>,
  <<Annotations>>, and <<content-keywords,Content keywords>>.

* JSON Schema (n.d.).
  https://json-schema.org/understanding-json-schema/reference/conditionals[_Applying Subschemas Conditionally_]. — The
  source for the `if`/`then`/`else` and `dependentRequired`/ `dependentSchemas` guidance in <<conditional-validation,Conditional validation>>.

* JSON Schema (n.d.). https://json-schema.org/understanding-json-schema/reference/format[_Format_]. — The source for the
  annotation-vs-assertion distinction for `format` in <<Format>>.

* JSON Schema (n.d.).
  https://json-schema.org/understanding-json-schema/reference/composition[_Modular JSON Schema Combination_]. — The
  source for the `$defs`, `$anchor`, `$dynamicAnchor`/`$dynamicRef`, and recursive-schema guidance in
  <<schema-identification,Schema identification>>.

* Devzery (n.d.).
  https://www.devzery.com/post/your-ultimate-guide-to-schema-for-json[_Your Ultimate Guide to Schema for JSON_]. — The
  source for the document-skeleton guidance (`$schema`, `$id`, `title`, `description`) in <<schema-identification,Schema identification>>.

* IETF (2013). RFC 6902. https://datatracker.ietf.org/doc/html/rfc6902[_JavaScript Object Notation (JSON) Patch_]. — The
  source for the operation model in <<json-patch,JSON Patch>>.

* Ajv (n.d.). https://ajv.js.org/[_Ajv JSON Schema Validator_]. — The source for the `ajv` entry in
  <<validator-libraries,Validator libraries>>.

* Ajv (n.d.). https://ajv.js.org/json-type-definition.html[_JSON Type Definition_]. — The source for the schema forms,
  `nullable`/`metadata`, `definitions`, and migration guidance in <<json-type-definition-jtd,JSON Type Definition (JTD)>>.

* Devzery (n.d.).
  https://www.devzery.com/post/your-ultimate-guide-to-schema-for-json#best-practices-for-using-json-schema[_Your Ultimate Guide to Schema for JSON_].
  — The source for <<schema-versioning,Schema versioning>>.

* LinkedIn (n.d.).
  https://www.linkedin.com/advice/1/how-do-you-keep-your-json-data-models-consistent[_How Do You Keep Your JSON Data Models Consistent?_].
  — The source for <<best-practices,Best practices>>.

* PayPal (n.d.).
  https://github.com/levid-gc/paypal-api-standards/tree/master/v1/schema/json/draft-04[_PayPal API Standards — JSON Schema examples_].
  — The source for the monetary-value, phone-number, vendor-prefixed `format`, file-organization, and error/envelope
  patterns in <<modeling-patterns,Modeling patterns>> and <<Cross-references>>.

* ITU-T (2010).
  https://www.itu.int/rec/T-REC-E.164/en[_E.164: The International Public Telecommunication Numbering Plan_]. — The
  source for the phone-number structure in <<modeling-patterns,Modeling patterns>>.
