= Asciidoctor extensions

AsciiDoc syntax can be extended by developing your own Asciidoctor extensions. Extensions are written in the language of the Asciidoctor implementation that runs them: Ruby for Asciidoctor itself, JavaScript for Asciidoctor.js, which is the implementation Antora uses, and Java for AsciidoctorJ.

Use of extensions is generally discouraged as they can make it harder to process the AsciiDoc files with different tools, and source files become less portable. An extension written for one implementation does not run on the others. Where an extension is used, it SHOULD be one that is widely adopted and actively maintained, and the project's documentation MUST record that the extension is needed to build the content.

== Diagrams

Diagrams are the most common reason to use an extension. AsciiDoc has no built-in support for diagrams. An extension such as {link-asciidoctor-diagram}[Asciidoctor Diagram] or {link-kroki}[Kroki] lets a diagram be written as text, in a language such as PlantUML or Mermaid, inside a block in the document. The diagram is rendered to an image when the document is built.

[source,asciidoc]
----
[plantuml,request-flow,svg]
....
Client -> Gateway: request
Gateway -> Origin: request
Origin --> Gateway: response
Gateway --> Client: response
....
----

Diagrams written as text SHOULD be preferred to image files drawn in a graphics tool, because their source can be reviewed and compared like any other text. Where the toolchain cannot run a diagram extension, keep the diagram's source in the repository alongside the rendered image file, and embed the image in the usual way.
