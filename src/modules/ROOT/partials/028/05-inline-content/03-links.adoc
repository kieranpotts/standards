[#links]
= Links

In AsciiDoc, links can be either external or internal.

* External links reference content outside the documentation, such as a web page.

* Internal links reference content inside the documentation, such as another page or a section within a document.

A link macro MUST NOT be broken across lines. The whole macro — the target, the square brackets, and the link text between them — MUST sit on a single source line.

For guidance on writing effective link text, see xref:026.adoc[*TS-26: Technical Writing Style Guide*].

[TIP]
======
Use a link checker to audit for broken links.
======

== External links

An external link SHOULD be written using the following syntax.

[source,asciidoc]
----
http(s)://domain/path?query#anchor[Hyperlinked text]
----

The `[Hyperlinked text]` part is optional. If it is omitted, the URL itself will be used as the hyperlink text.

For external links, the `link:` prefix is required only when the target is not a URI. AsciiDoc recognizes `http:` and `https:` as URI protocols and handles them as implicit `link:` macros.

If you want to prevent a link from being automatically hyperlinked, prepend it with a backslash (`\`). The text will be rendered verbatim as normal, non-clickable text.

[source,asciidoc]
----
\https://www.example.com/
----

A URL may not display correctly when it contains characters such as underscores (`_`), carets (`^`), or double quotes (`"`). The following is an example of a URL containing characters that need special treatment. See {link-asciidoctor-complex-urls}[Asciidoctor: Troubleshooting Complex URLs] for help solving this.

[source,asciidoc]
----
https://www.owasp.org/index.php/Cross-site_Scripting_(XSS)
----

External URLs used for links MAY be declared as a document-level attribute. It is RECOMMENDED to prefix the unique attribute name with `link-`.

[source,asciidoc]
----
= The page header
:link-name: https://example.com/content/link_can_be_very_long

Text {link-name}[highlighted text] text.
----

== Internal links

Internal links are used to create cross-references to:

* an in-page reference;
* a documentation file;
* a section title or anchor name inside a documentation file.

=== In-page cross-references

An in-page cross-reference points to a specific location within the same document. The target MUST be given an explicit anchor using the `[#<id>]` block attribute syntax, placed directly above the element it labels.

[source,asciidoc]
----
[#worse-is-better]
== Worse is better

The "worse is better" philosophy...
----

The cross-reference MUST then refer to the anchor by its ID, not by the section title.

[source,asciidoc]
----
See <<worse-is-better>> for details.
----

Relying on Asciidoctor's auto-generated anchor IDs — which are derived from section titles — is NOT RECOMMENDED. Auto-generated IDs change whenever a section is renamed, silently breaking references. Explicit anchor IDs are stable, decoupled from prose, and make it straightforward to mechanically verify that every `<<...>>` reference resolves to a defined `[#...]` anchor.

The older `[[<id>]]` double-bracket syntax is equivalent for a block-level anchor and MAY still be encountered, but `[#<id>]` is preferred. It is the same shorthand used for roles (`.role`) and options (`%option`), so it composes with them in one attribute list (`[#id.role]`) where `+[[id]]+` cannot. However, `[[<id>]]` remains the only option for an inline anchor — a point marked in the middle of a sentence or list item rather than on a block of its own — since the `[#id]` shorthand only attaches to a block.

=== Cross-references to other documents

A cross-reference to another documentation file, or to an anchor inside one, MUST be written with the `xref:` macro. The target is the path to the AsciiDoc source file, including its `.adoc` extension, optionally followed by a number sign (`#`) and the ID of an anchor in that file.

[source,asciidoc]
----
See xref:installation.adoc[Installation] for the prerequisites.

See xref:installation.adoc#supported-platforms[Supported platforms] for details.
----

A cross-reference MUST NOT be written as a link to the rendered output, such as an `.html` file or a published URL. The processor cannot check such a link, and it breaks when the output format or the site structure changes.

In a site built with Antora, the target of a cross-reference is a resource ID rather than a file system path. See <<antora,Antora>>.

== Bold links

To make linked text bold, two syntaxes are supported.

[source,asciidoc]
----
https://domain/path[*Hyperlinked text*]
*https://domain/path[Hyperlinked text]*
----

Same for internal links.

[source,asciidoc]
----
xref:NNN.adoc[*Hyperlinked text*]
*xref:NNN.adoc[Hyperlinked text]*
----

Both produce the expected result, but the inner form — bold applied tightly around the link text, inside the macro's brackets — SHOULD be preferred. Bolding the whole link construct, brackets included, is NOT RECOMMENDED.
