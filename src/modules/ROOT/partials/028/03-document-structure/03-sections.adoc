[#sections]
= Sections

Sections are used to partition the content of a document into a hierarchy. A section title represents the heading for that section.

Document titles and section titles SHOULD be written in sentence case, not title case, with no termination punctuation. "The quick brown fox jumps over the lazy dog", not "The Quick Brown Fox Jumps Over the Lazy Dog".

Capitalize only the first word and any proper nouns, eg. "Amazon Web Services (AWS)".

See xref:026.adoc[*TS-26: Technical Writing Style Guide*] for the full rationale.

Section title levels are specified using two to six equals signs (`=`). The number of equals signs in front of the title represents the nesting level (using a 0-based index) of the section.

[source,asciidoc]
----
= Document title (level 0)

// Content here.

== Level 1 section title

// Content here.

=== Level 2 section title

// Content here.
----

Section levels MUST increase in single steps. Asciidoctor will emit a warning when jumping from `==` to `====`, for example.

Sections automatically create a reference-able anchor, and they are automatically added to tables of contents. In the rare case that you want a heading that is left out of the TOC, add `[discrete]` above it. A discrete heading keeps its anchor for cross-references, but it does not open a new section, so it is not part of the section hierarchy.

[source,asciidoc]
----
[discrete]
=== Level 2 section title
----
