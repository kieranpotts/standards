= Descriptive versus prescriptive

Most forms of documentation SHOULD describe the current state of the software, not future aspirations or intentions for it. Documentation written before implementation quickly drifts from reality as plans, designs, and implementations naturally evolve.

To stay accurate, documentation SHOULD _follow_ implementation rather than _precede_ it.

However, there will be plenty of valid exceptions to this rule, such as proposals for software requirements specifications and other process artifacts.
