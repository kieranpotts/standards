= Ownership

Each type of documentation MUST have clear ownership. Documentation without an owner tends to rot silently, because no one notices when it drifts from the system it describes, and no one is accountable for fixing it.

Reference documentation — eg. READMEs, API docs, and architecture docs — SHOULD be owned by whoever owns the code it describes, and updated in the same revisions that change the described behavior. Thus, a pull request that changes an API's behavior without also updating the API documentation SHOULD be treated as incomplete.

Where documentation cannot reasonably be kept current — eg. because it describes a system no one maintains, or a decision that predates the current team — mark it explicitly as historical.
