= API documentation

Where practical, API documentation SHOULD be generated from the code itself, rather than hand-written and maintained separately. For example, an OpenAPI specification generated from route and type definitions, or reference docs generated from typed function signatures and docstrings.

Where generation isn't practical, eg. documenting a third-party API, or a protocol rather than a code interface, hand-written API documentation MUST still describe the interface as it currently behaves, not as it was designed to behave.

At a minimum, API documentation MUST specify the following, per operation.

* Inputs (including required versus optional, and types).
* Outputs.
* Error conditions.
* Side effects.
