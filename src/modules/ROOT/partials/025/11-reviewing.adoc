= Reviewing documentation

A small set of fresh, accurate documentation is better than a sprawling, loose assembly of documentation in various states of disrepair. So, outdated content SHOULD be deleted in small, regular increments, rather than being left to accumulate into a single overdue cleanup that never happens.

This requires documentation to be regularly reviewed.

Reviewing documentation is not the same discipline as reviewing code. It is usually not necessary to apply the same rigor to documentation review as to code review. For example, reviewers SHOULD NOT block a documentation change over matters of style or preference. Only factual inaccuracies justify withholding approval. Anything else SHOULD be approved with suggestions, or raised as a separate follow-up change.
