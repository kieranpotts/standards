This technical standard covers documentation written for the people who use a software product to get something
done — end users, not developers. It applies to help centers, in-product help, onboarding guides, and any other
material that explains how to operate the product rather than how it is built.

This is a narrower concern than technical documentation in general. For documentation aimed at engineers, operators,
and other contributors — READMEs, API references, architecture docs, runbooks — see
xref:025.adoc[*TS-25: Technical documentation*], whose section on UX writing also covers the words that appear
inside the product itself — button labels, error messages, empty states. A user manual is the material a reader
seeks out deliberately, in addition to that in-context UI text. For sentence-level writing conventions that apply to
any document, technical or otherwise, see xref:026.adoc[*TS-26: Technical writing style guide*].
