= Quotation marks

Use plain, straight double quotes — `"like this"` — for quoted prose. Do not write verbatim curly quotes, or use AsciiDoc's curly-quote syntax, `` "`like this`" ``.

Use single quotes only for a quotation nested inside another quotation.

Place punctuation that follows a quoted phrase outside the closing quotation mark, unless the punctuation is part of the quoted material itself. This applies to periods and commas as well as to colons, semicolons, question marks, and exclamation points. The quotation marks enclose exactly what is being quoted, which matters where the exact characters count, such as a string, a status message, or a term.

----
✅ The response returns "not found".
✅ The states are "pending", "active", and "closed".
✅ Set the label to "Save changes"; leave the tooltip empty.
✅ Did the API return "forbidden"?
❌ The response returns "not found."
❌ The states are "pending," "active," and "closed."
----

Place a period or comma inside the closing quotation mark only when transcribing a conversation, such as an interview, a quoted message, or a dialogue, where the punctuation belongs to the speech being reproduced.

----
✅ She said, "We can't ship until the migration finishes."
✅ "The migration is done," he replied, "so we can ship."
----

Backticks MUST NOT appear inside a quoted string in prose. Quote the phrase or set the term in monospace, never both. Pick the one that reflects what the text represents.

----
✅ "list responses within 300 ms at the 95th percentile"
✅ The `Scenario Outline` keyword.
❌ "the `Scenario Outline` keyword"
----

This applies to prose only. Backticks inside a code block are untouched by this rule, including where the language being shown uses them as syntax.
