= Tone

Write in a plain, factual register. Technical documentation states facts and lets the reader judge their significance. It does not sell, cheer, or chat.

Avoid marketing words in technical writing, eg. "boasts", "vibrant", "cutting-edge", "seamless", "robust". Unearned superlatives and buzzwords — , eg. "revolutionary", "game-changing", "next-generation", "best-in-class", "state-of-the-art", "powerful", "intuitive", "elegant" — are the same problem in a different guise.

Bad: "A powerful, intuitive API for managing subscriptions."

Good: "An API for managing subscriptions, with one call per lifecycle event."

Watch for words chosen because they sound weighty rather than because they are precise, eg. "delve", "leverage", "foster", "landscape" (used abstractly), "tapestry", "intricate", "crucial". None is forbidden outright, but a document that leans on several of them reads as padded. Rewrite with plainer words.
