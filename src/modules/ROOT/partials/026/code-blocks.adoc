= Code blocks

Code blocks SHOULD specify their language, where the markup format supports it. This allows syntax highlighting to be applied in some generated output formats.

Keep code examples narrow enough to avoid horizontal scrolling in a typical rendered format. Wrap or truncate long lines.

Do not prefix CLI commands with a dollar sign (`$`). Many rendering systems let readers copy the content of a code block, and a prompt in the copied text stops the command from running when it is pasted into a terminal.

[source,markdown]
----
```sh
git clone git@<hostname>:<group>/<project>.git
```
----

The exception to this rule is when documenting the output from CLI commands. In this case, including the prompt can help to clarify which lines are commands and which lines are output.

[source,console]
----
$ heroku logs --help
display recent log output

USAGE
  $ heroku logs

OPTIONS
  -a, --app=app        (required) app to run command against
  -d, --dyno=dyno      only show output from this dyno type
  -n, --num=num        number of lines to display
  -r, --remote=remote  git remote of app to use
  -s, --source=source  only show output from this source
  -t, --tail           continually stream logs
  --force-colors       force use of colors (even on non-tty output)

DESCRIPTION
  disable colors with --no-color, HEROKU_LOGS_COLOR=0, or HEROKU_COLOR=0

EXAMPLES
  $ heroku logs --app=my-app
  $ heroku logs --num=50
  $ heroku logs --dyno=web --app=my-app
  $ heroku logs --app=my-app --tail
----

A multi-line shell or command snippet intended to be copy-pasted as a single command MUST escape its newlines with a trailing backslash.

[source,sh]
----
gcloud compute instances create example-instance \
  --zone=us-central1-a \
  --machine-type=e2-medium
----

For the conventions on placeholders in code blocks, see Placeholders.
