= Headings

Use sentence case for headings — eg. "Referencing style guides" — not title case — eg. "Referencing Style Guides". Sentence case is faster to read, easier to write consistently, and avoids the ambiguity of which words to capitalize.

This applies equally to document titles, not just section headings within a document. Capitalize only the first word and any proper nouns. Examples: "Distributed system design", "Getting started with Kubernetes", "Amazon Web Services (AWS)". The one exception is the title of a technical standard itself, in the form "TS-N: Title", which is set in title case as the name of a published work.

This letter case rule applies only to document titles and subsection headings. The title of an external work, when cited, follows a different rule. See Titles of works.

Headings SHOULD describe the content that follows, not tease it or ask a question, except for the entries in a FAQ section. Prefer "Configuration options" over "What can you configure?".

Do not skip heading levels, eg. jumping from a level-1 heading to a level-3 heading. This breaks the document outline and assistive-technology navigation.

Nest headings only as deeply as the content actually warrants up to a maximum of level-4 (where the document title in level-1).

Do not set any part of a heading in monospace, bold, or italic. A heading is already visually distinct by its size and weight, and inline formatting on top of that can confuse rendering issues in some cases.
