= Tooling

A linter SHOULD be used to enforce consistent YAML style across a project.
https://yamllint.readthedocs.io/[yamllint] is RECOMMENDED. It is
configurable per-project and checks indentation consistency, line length,
trailing whitespace, duplicate keys, and the truthy/boolean ambiguity
described in <<implicit-typing,Booleans, nulls, and implicit typing>> (its
`truthy` rule restricts implicit booleans to `true`/`false` by default,
catching the Norway problem at lint time).

A formatter such as https://prettier.io/[Prettier] or
https://github.com/google/yamlfmt[yamlfmt] MAY be used to automate
indentation and quoting style. Formatting and linting SHOULD be reconciled
so they do not produce conflicting results.

Editor/IDE integration via the
https://github.com/redhat-developer/yaml-language-server[YAML Language Server]
SHOULD be used where available, for real-time schema validation and syntax
checking (see <<Schema validation>>).

A YAML parser's safe/restricted loading mode SHOULD be the one exercised in
CI validation, matching the mode used at runtime (see <<Security>>), so
that a document which fails to parse safely is caught before merge rather
than in production.

Editor configuration SHOULD ensure:

* Tabs are never inserted for indentation (see
  <<Indentation>>).
* Trailing whitespace is highlighted.
* Files end with a single newline character.
