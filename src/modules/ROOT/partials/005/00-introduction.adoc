This technical standard sets out principles and best practices for designing and implementing standalone software
applications.

An "application" is defined here as a software component that is deployed in a single operation, is usually maintained
in a single repository, and is designed to perform a specific function or set of functions. Many applications will be
designed to run in a single process (but there are plenty of applications that are designed to spawn multiple processes
for performance reasons). An application may be a standalone executable, a library, or a service or microservice within
a larger distributed system.

In client-server systems such as web applications, the client-side application may specialize in only the user
interface, while the server-side application specializes in data processing, business logic, and state persistence. GUI
applications tend to require a specialist architecture, which is outside of the scope of this technical standard. See
xref:018.adoc[*TS-18: Web GUIs*] for guidance on designing client-side web applications.

Related technical standards include xref:002.adoc[*TS-2: Software design philosophy*], which describes general software
architectural design best practices and standards; and xref:007.adoc[*TS-7: Code design*], which covers concerns such as
code formatting and low-level design patterns.

See also xref:046.adoc[*TS-46: Distributed data and caching*], which is an important consideration in application
architecture.
