[#line-length]
= Line length and wrapping

Prose MUST NOT be "soft wrapped" — that is, continued on the next source line without any special line-break syntax. Each paragraph, list item, blockquote paragraph, callout body, and table cell MUST be written on a single source line, however long that line is.

CommonMark joins the adjacent lines of a paragraph into a single line in the rendered output, so a soft wrap usually makes no difference to how a document renders. The risk is in the exceptions. A wrap that falls inside an inline construct — a bold or italic span, an inline code span, a link — separates the markup from the text it applies to, and depending on the construct, it may silently fail to render, or fail loudly by rendering the raw syntax as literal text. The wrap points also shift every time a sentence is edited, which invites exactly that kind of breakage when a paragraph is reflowed by hand or by a tool. Keeping each paragraph on one line removes the whole class of problem.

Visual wrapping is left to the editor. Authors SHOULD enable soft wrapping in their editor's display settings (eg. `"editor.wordWrap": "on"` in VS Code) rather than in the source text. Because a one-word edit changes a paragraph's whole line, reviewers SHOULD use a word-level diff (eg. `git diff --word-diff`) to read changes to prose.

Where a line break is needed in the rendered output, use a hard line break. See <<paragraphs-and-line-breaks,Paragraphs and line breaks>>.

The rule applies to prose only. It does not apply to:

* *Verbatim content.* Fenced and indented code blocks keep the line structure their content needs. Code samples follow the line-length rules of the relevant language standard, and reformatting a sample to fit a prose line-length guideline would misrepresent it.

* *Hard line breaks.* A line that ends with a hard line break (a trailing backslash, or two or more trailing spaces) is intentional, and the text that follows it stays on its own line.

* *Table rows.* The cells of a table row MAY be written one per line. Each cell's content is itself prose, so it MUST NOT be soft wrapped.

A heading MUST NOT be broken across lines in any case. Markdown has no continuation syntax for a heading, so a wrap would either break it or become part of the heading text.
