[#line-length]
= Line length and wrapping

In CommonMark, a single newline inside a paragraph is a soft break, and it renders as a space. A paragraph split across several source lines therefore renders identically to the same paragraph written on one line. How prose is wrapped in the source is therefore a decision about editing, and the presentation of diffs in code review, not about rendering.

For the three common approaches to wrapping prose in the source, their costs and benefits, and the ground rules that apply whichever approach is chosen, see xref:026.adoc[*TS-26: Technical Writing Style Guide*].

For Markdown, the one-line-per-paragraph style is RECOMMENDED. Each paragraph and list item sits on a single source line. No wrap point can fall inside a link or an emphasized phrase, and the text is safe to paste into tools that render every newline as a line break, as GitHub does in issue and pull request comments. Where a line break is needed in the rendered output, use a hard line break. See <<hard-line-breaks,Hard line breaks>>.

Wrapping applies to prose only. Fenced and indented code blocks keep the line structure their content needs, and code samples follow the line-length rules of the relevant language standard. Other Markdown constructs, such as headings and table rows, do not support multiline syntax, so each MUST sit on a single source line.
