= Links

Links are written by enclosing the link text in square brackets, immediately followed by the URL in parentheses.

----
My favorite search engine is [Duck Duck Go](https://duckduckgo.com).
----

A link MUST NOT be broken across lines. The whole construct — the bracketed text, the parenthesized URL, and the boundary between them — MUST sit on a single source line. Where a long URL makes the line uncomfortable to work with, use a reference-style link instead. See <<reference-style-links,Reference-style links>>.

An optional title may be added in double quotes after the URL. The title is displayed as a tooltip in most renderers.

----
[Duck Duck Go](https://duckduckgo.com "A privacy-focused search engine")
----

For guidance on writing effective link text, see xref:026.adoc[*TS-26: Technical Writing Style Guide*].

[#reference-style-links]
== Reference-style links

Reference-style links separate the link text from the URL, which can improve readability in documents that contain many long URLs. The link is written as `[text][label]`, and the URL is defined elsewhere as `[label]: url "optional title"`.

----
See the [CommonMark spec][cm] for details.

[cm]: https://spec.commonmark.org/ "CommonMark Specification"
----

Reference-style links are most useful where an inline link would disrupt the surrounding prose, such as a long URL that would push the line well past the usual length, a link that needs to appear inside a table cell, or a destination that is linked to more than once in the same document. For a short link used once, an inline link is simpler and keeps the destination visible at the point of use.

Reference definitions MAY be placed immediately after the paragraph that uses them or at the end of the document.

== Bare URLs

Bare URLs and email addresses SHOULD be enclosed in angle brackets, to ensure they are auto-linked.

----
<https://www.example.com>
<user@example.com>
----

To prevent a URL from being auto-linked, wrap it in backticks.

----
`https://www.example.com`
----

== URL encoding

Spaces and parentheses in URLs can cause parsing problems. Spaces in URLs SHOULD be URL-encoded as `%20`. Where a URL contains parentheses, enclose the URL in angle brackets, inside the link's own parentheses, or use a reference-style link.

----
[Markdown](<https://en.wikipedia.org/wiki/Markdown_(disambiguation)>)
----

== Links to other files

A link to another file in the same repository SHOULD use an explicit path, including the `.md` extension, rather than relying on the target platform to infer it.

----
✅ See the [contribution guide](../docs/CONTRIBUTING.md).
❌ See the [contribution guide](../docs/CONTRIBUTING).
----

Relative paths that climb outside the current directory (`../`) SHOULD be avoided, except where the target is genuinely close by.

== Links to headings

A link to a heading is written with a number sign (`#`) followed by the heading's anchor. The anchor MAY follow a file path, to link to a heading in another file.

----
See [Configuration](#configuration) for the available options.

See [Installing on Linux](./install.md#installing-on-linux).
----

Heading anchors are not part of CommonMark. Each renderer generates them by its own rules, and the anchor changes whenever the heading text is edited. A link to a heading SHOULD therefore be checked on the platform where the document is published, and re-checked when the heading is reworded. See <<headings,Headings>>.
