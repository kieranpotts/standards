= Tooling

A linter SHOULD be used to enforce consistent Markdown style across a project. https://github.com/DavidAnson/markdownlint[markdownlint] is RECOMMENDED. It is configurable and widely supported.

A code formatter such as https://prettier.io/[Prettier] MAY be used to automate list indentation and code-block formatting. BUt it MUST NOT be configured to reflow prose. Set Prettier's `proseWrap` to `never`, so each paragraph is put back onto a single line, or to `preserve`, so it leaves line structure alone.

Any linter rule that caps line length — eg. markdownlint's `MD013` — MUST be disabled for prose.

Formatting and linting configurations MUST be reconciled so they do not produce conflicting results.

A link checker SHOULD be run as part of continuous integration to detect broken internal and external links.

It is RECOMMNEDED that code editors have the following settings.

* Long lines are soft wrapped for display (eg. `"editor.wordWrap": "on"` in VS Code).
* Trailing whitespace is highlighted.
* Files end with a single newline character.
* Indentation uses spaces, not tabs.
