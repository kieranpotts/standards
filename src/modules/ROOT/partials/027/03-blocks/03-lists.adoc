= Lists

== Unordered lists

Unordered lists use a hyphen (`-`) followed by a single space. Do not mix markers (`-`, `*`, `+`) within the same list.

----
- First item
- Second item
- Third item
----

== Ordered lists

Ordered lists use a number followed by a period and either one or two spaces.

----
1. First item
2. Second item
3. Third item
----

Two spaces are RECOMMENDED where list items carry continuation paragraphs or nested blocks. It puts the content at a four-space indent, so everything that belongs to an item lines up on a regular tab stop.

----
1.  First item.

    Continuation paragraph, aligned with the item text.

    - A nested item, at the same indent.
----

CommonMark does not require the numbers in an ordered list to be sequential. But, for a short, stable list, sequential numbering in source (`1.`, `2.`, `3.`) is RECOMMENDED, since it is easy to read directly and rarely needs maintenance. For a long list, or one that is edited frequently, "lazy" numbering — repeating `1.` for every item — MAY be used instead. The rendered output is the same, either way.

----
1. First item
1. Second item
1. Third item
----

== Nesting and continuation

Nested lists are created by indenting child items. To include multiple paragraphs or other block elements in a single list item, indent the continuation lines in the same way.

A nested item, and any continuation paragraph or other block that belongs to a list item, MUST be indented to align with the first character of the parent item's text, ie. the indentation size is the number of characters in the list marker plus its trailing space. That is two spaces beneath an item marked `-`, and four spaces beneath an item marked `1.` with two trailing spaces. Indentation MUST be consistent throughout a list.

----
- First item.

  Continuation paragraph, aligned with the item text.

  - A nested item, at the same indent.
----

A fenced code block inside a list item MUST be indented to that same column.

----
1.  First item.

    ```sh
    echo "This code block belongs to the list item."
    ```

2.  Second item.
----

== Spacing between items

Items longer than a short phrase — in particular, any item written as one or more full sentences — SHOULD be separated from each other by a blank line, matching how paragraphs are separated. This materially improves the readability of the plain text source. Short items MAY be kept tight, without blank lines between them.

----
- This is the first item. It is written as full sentences.

- This is a separate item.

- This is another item in the same list.
----

For content, lists work best when each item is no longer than one or two short sentences.

== Lead-in terms

A common pattern is to bold a short lead-in term at the start of each item, followed by a full sentence explaining it. For how lead-in terms are punctuated, see xref:026.adoc[*TS-26: Technical Writing Style Guide*]. In Markdown, the pattern is written as follows.

----
- **Performance.** The system responds to user input within 100 ms under normal load.

- **Reliability.** The system continues to operate correctly in the presence of hardware or software faults.

- **Scalability.** The system handles growth in data volume, traffic, or complexity without a redesign.

- **Maintainability.** The system is easy for engineers to understand, modify, and extend over time.
----

Another pattern, supported by Markdown's hard line break syntax, is to put the lead-in term on its own line and indent the text beneath it. This has the visual effect of better differentiating the lead-in term, so it is rendered more like a heading.

----
- **Performance.** \
  The system responds to user input within 100 ms under normal load.

- **Reliability.** \
  The system continues to operate correctly in the presence of hardware or software faults.

- **Scalability.** \
  The system handles growth in data volume, traffic, or complexity without a redesign.

- **Maintainability.** \
  The system is easy for engineers to understand, modify, and extend over time.
----

For lists of key-value pairs, place the colon inside the bold marker.

----
- **Status:** Active
- **Owner:** Platform team
- **Region:** eu-west-1
- **Version:** 2.4.0
----

== Task lists

GFM task lists MAY be used where the rendering platform supports them.

----
- [x] Completed task
- [ ] Outstanding task
----
