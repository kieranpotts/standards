# TS-61 deep dive

Findings from a deep review of TS-61: AI Tools, sections 13 to 21 (`13-model-context-protocol.adoc` to `21-security.adoc`). Sections 1 to 12 were reviewed separately and are cited here only where a later section contradicts or duplicates them.

~1,170 lines across 9 files.

Assessed against the repository [style guide](../../../../../docs/style-guide.md), [TS-26: Technical Writing Style Guide](https://kieranpotts.com/standards/026), [TS-27: Markdown](https://kieranpotts.com/standards/027), [TS-28: AsciiDoc](https://kieranpotts.com/standards/028), and the [template](../../../../../template/). Factual claims were checked against primary sources on 2026-10-13, and each source is named in its finding.

**Assessment.** The technical content is sound and the individual sections are well argued. The MCP, harness, and security material holds up against the primary sources almost everywhere. The problems are of three kinds. The same rule is restated in several sections and the copies have drifted, which accounts for most of the 15 contradictions. Removing the internal cross-references left several sentences broken or dangling. And the security section has grown into a catch-all that repeats sections 13 and 17. Every cross-reference and include in these nine files resolves, and there are no soft-wrapped lines.

**Status:** All four tiers applied, with one tier 1 item open: the loop-engineering reference check (section 18), which needs a primary source that could not be found. The tier 3 and tier 4 fixes were mostly found already present in the files when the tiers were worked, so those tiers were largely verification. File names are current. Line numbers in tier 4 are as of the original review.

## Priority order

1. **Correctness.** Contradictions and factual errors. A reader cannot comply with a standard that says two incompatible things.

2. **Coherence.** Structural problems. Structure must settle before content is added to it.

3. **Completeness.** Coverage gaps. Filled into a structure that has stopped moving.

4. **Conventions.** Style-guide conformance. Last, because content edits invalidate cosmetic fixes made too early.

- [x] `20-cost-optimization.adoc:20` claims GitHub Copilot meters its allowance "in requests" and counts a frontier-model request "as several". Dropped the Copilot example and generalized to usage weighted by model or converted to credits.

- [x] `17-agentic-workflows.adoc:55` claims exact multi-step computation such as "arithmetic on large numbers" is "computationally irreducible". Wolfram's term describes systems whose outcome cannot be found by any shortcut faster than running them. Arithmetic is the standard counter-example, because it has shortcuts. The accurate point is narrower: a model does not execute an algorithm, so its output is not exact. Drop the term. Done. Replaced "computationally irreducible" with "no pattern-matching shortcut".

- [x] `19-evaluation.adoc:74` claims "a difference of a few percentage points needs hundreds" of runs. At conventional settings (two-sided 5% significance, 80% power) detecting 80% against 83% needs about 2,600 runs in each configuration, and 50% against 53% about 4,300. Hundreds detects roughly 10 percentage points. Change "hundreds" to "thousands". The same paragraph says to run the baseline "twice" to measure noise, which yields a single difference. Say "several times". Done. "Hundreds" became "thousands of runs in each configuration", and "twice" became "several times".

- [x] `21-security.adoc:45` claims that for LAN access "binding to `0.0.0.0` is necessary". It is not. Binding to the address of the one LAN interface gives LAN access without listening on every interface, and is the narrower setting. State that as the preference and keep the firewall rule for the `0.0.0.0` case. Done. Now prefers binding to the LAN interface address. The firewall MUST applies to `0.0.0.0`, and the key requirement at 21:5 is unchanged.

- [x] `20-cost-optimization.adoc:82` describes "a single gateway subscription (such as OpenRouter)". OpenRouter sells prepaid credits at each provider's token price plus a fee. It is not a subscription, and `20-cost-optimization.adoc:22` has just said a subscription's marginal token cost is zero, so a metered gateway is rarely cheaper than the subscriptions it would replace. Reword as a metered gateway compared with several metered API accounts. Done. Now a metered gateway, with a note that gateways typically add a fee.

- [x] `20-cost-optimization.adoc:64` claims "output economy matters more than input economy". That is true of unit price only. `20-cost-optimization.adoc:36` and `18-loop-engineering.adoc:86` both say input is re-sent on every call, and in an agent loop input volume usually dominates the bill. Qualify the claim as per token. Done. Qualified as per-token, and noted that input volume often dominates in an agent loop.

- [x] `21-security.adoc:124` claims "One or two parts of the trifecta in isolation are comparatively safe." That holds for exfiltration only. An agent with untrusted content and write access can delete files or commit malicious code with no private data and no outbound channel, as `21-security.adoc:240` itself notes.
