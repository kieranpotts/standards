= Modeling levels

Models are abstract representations of a system's functionality and data flow. Models can be created at different levels of abstraction, each offering different levels of detail and different insights.

The following is a useful general-purpose mental model to think about the levels of abstraction possible in software models. From high-to-low:

* *Conceptual architecture*: The most abstract and least detailed view. It provides a strategic, high-level overview of the whole system, defining the major components and how they interact.

* *Logical architecture*: Describes how systems work in terms of functions and logical information flows, abstracting away implementation details.

* *Physical architecture*: The lowest level of abstraction, concerned with specific services, software components, data representations, and the physical or virtual devices on which they run. These models map the logical architecture to concrete infrastructure, providing the detailed guidance that technical teams need to build, monitor, and maintain the system. Components that may be represented include clients, servers, load balancers, databases, storage, caches, message queues, and external services.

* *Technical design*: A catalog of the specific computer languages, runtime environments, and system software used in production systems.

Different levels of abstraction are suitable for different use cases. For example, conceptual architecture models, which don't go into technical details, tend to be useful for discussing a system's design with non-technical stakeholders.
