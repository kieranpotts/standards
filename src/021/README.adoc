A smart API will make lots of decisions for clients, eg. pre-format error messages, rather than leaving clients to construct human-friendly error messages from raw server data and error codes. There is no right or wrong approach, but smart APIs really only required when their primary use case is to back a single GUI, rather than be integrated with lots of different client applications.
