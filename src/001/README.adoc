= TS-1: Software Requirements Specification
:toc: macro
:toc-title: Contents

This technical standard covers best practices for defining and managing software
requirements.

[quote, Louis Srygley]
____
Without requirements or design, programming is the art of adding bugs to an
empty text file.
____

A software requirements specification (SRS), also known as a system requirements
specification, defines the acceptance criteria (ACs) for a software system. It
is the basis for the software's design, implementation, and verification.

This technical standard covers two aspects of requirements specification:

* _What_ a good requirements specification looks like.

* _How_ a specification is managed over time so it stays an accurate, trusted
  description of the system as it actually is in production.

A reference implementation of everything described here is maintained separately
at https://github.com/kieranpotts/specs[kieranpotts/specs].

* Brandolini, A (2013).
  https://leanpub.com/introducing_eventstorming[_Introducing EventStorming_].
  Leanpub. — The origin of the technique, first postulated in a
  https://ziobrando.blogspot.com/2013/11/introducing-event-storming.html[2013 blog post].

* Jacobson, I (1992).
  https://www.amazon.com/dp/0201544350[_Object-Oriented Software Engineering: A Use Case Driven Approach_].
  Addison-Wesley. — The book that introduced use case analysis.

* Cohn, M (2004).
  https://www.amazon.com/gp/product/0321205685/[_User Stories Applied: For Agile Software Development_].
  Addison-Wesley. — The standard treatment of user stories in requirements
  gathering. See also Cohn's
  https://www.mountaingoatsoftware.com/agile/user-stories[User Stories and User Story Examples]
  and
  https://www.mountaingoatsoftware.com/articles/advantages-of-user-stories-for-requirements[Advantages of User Stories for Requirements].

* Patton, J. https://jpattonassociates.com/story-mapping/[_Story Mapping_]. Jeff
  Patton & Associates. — The technique for arranging user stories into a
  two-dimensional map.

* Wynne, M (2015).
  https://medium.com/@mattwynne/introducing-example-mapping-42ccd15f8adf[_Introducing Example Mapping_].
  Medium. — The card-based workshop technique for breaking a story into rules
  and examples.

* Adzic, G. https://www.impactmapping.org/[_Impact Mapping_]. — The
  goal/actor/impact/deliverable framing for deciding what is worth building.

* Srivastava, PJ.
  https://www.pjsrivastava.com/blog/a-short-guide-to-writing-software-requirements/[_A Short Guide to Writing Software Requirements_].
  — Covers user stories, workflow diagrams, and the use of wireframes and visual
  diagrams.
