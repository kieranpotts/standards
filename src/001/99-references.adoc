= References

* https://leanpub.com/introducing_eventstorming[Introducing EventStorming] by Alberto Brandolini.
  Brandolini first postulated his EventStorming strategy for requirements gathering in a
  https://ziobrando.blogspot.co.uk/2013/11/introducing-event-storming.html[2013 blog post].

* https://www.pjsrivastava.com/blog/a-short-guide-to-writing-software-requirements/[A Short Guide to Writing Software Requirements], by PJ Srivastava.
  Covers user stories, workflow diagrams, and the use of wireframes and visual diagrams.

* Mike Cohn's writing on user stories and their utility in requirements gathering and specification:

  ** https://www.amazon.com/gp/product/0321205685/[User Stories Applied: For Agile Software Development]
  ** https://www.mountaingoatsoftware.com/presentations/introduction-to-user-stories[Introduction to User Stories]
  ** https://www.mountaingoatsoftware.com/agile/user-stories[User Stories and User Story Examples]
  ** https://www.mountaingoatsoftware.com/articles/advantages-of-user-stories-for-requirements[Advantages of User Stories for Requirements]

* https://www.amazon.com/dp/0201544350[Object-Oriented Software Engineering: A Use Case Driven Approach], by Ivar Jacobson.
  The book that introduced use case analysis.

* https://jpattonassociates.com/story-mapping/[Story Mapping], by Jeff Patton.
  The technique for arranging user stories into a two-dimensional map.

* https://medium.com/@mattwynne/introducing-example-mapping-42ccd15f8adf[Introducing Example Mapping], by Matt Wynne.
  The card-based workshop technique for breaking a story into rules and examples.
