= AI-assisted development workflows

Broadly, there are two approaches to incorporating AI-based coding tools into development workflows:

* **AI-assisted development workflows**, in which humans synchronously interact with AI tools to assist with current development challenges.

* **Agentic workflows**, in which harnesses are engineered to orchestrate one or more AI agents to perform development tasks with a high degree of autonomy, supporting asynchronous/parallel development workflows.

This section focuses on best practices for AI-assisted development workflows. Agentic workflows require additional guardrails to keep humans in-the-loop. This is covered in the next section.

''''

The most effective approach to AI-assisted development is to split complex tasks into distinct planning and implementation phases, matching model capabilities to task requirements. Premium, specialist models tend to do a better job at planning code changes than cheaper, general-purpose models, but the cheaper models are often perfectly capable of executing those plans. This optimizes output quality while reducing subscription costs.

Use frontier models for planning and architecture decisions, complex problem-solving, security analysis, and architectural compliance. Use efficient models for code construction from pre-approved plans, small-scale refactoring, and routine chores.

It is RECOMMENDED to follow this planning-implementation cycle for all but the simplest tasks.

== Planning phase

When using AI tools for planning code changes, provide comprehensive context including requirements, constraints, and existing architectural patterns. Request structured outputs, for example diagrams, pseudocode, or API specifications. Output should be _verifiable_, where possible.

Provide sufficient context in initial prompts to minimize clarification rounds. Provide code examples as context, to improve output quality.

Validate architectural decisions made by AIs against project standards _before_ implementing them. For large-scale or complex changes, document AI-assisted design decisions for team review first.

== Implementation phase

When using AI for code generation, provide clear, specific prompts based on pre-approved execution plans.

Define coding standards, style guides, and architectural conventions as concise, reusable prompt inputs – "skills" or "rules" – that can be injected into the context window at the start of an implementation session. Likewise, create reusable prompt templates for common, mundane tasks. Keeping these definitions token-efficient ensures they do not crowd out other high-signal context. When the AI produces code that deviates from a standard, feed back the relevant rule explicitly and ask it to revise.

Ask the AI to implement execution plans incrementally. This means generating code in small, stable, independently-deployable increments. It is easier to review and test code changes incrementally than in a single "big bang" changeset.

Batching together similar tasks reduces token consumption. But do this sparingly. Better to have a few smaller changesets than one large one to review.

Use version control to track changes to AI-generated code, and to provide a robust "undo" operation. Avoid making manual and automated changes to code in the same revision.

[TIP]
======
When an agent gets stuck, avoid contaminating the context with irrelevant information. Instead, ask directly: "What information do you need that would let you implement this perfectly right now?" This forces the agent to identify its own knowledge gaps rather than flailing blindly.
======

== Testing phase

All normal developer review and approval processes MUST remain in place for AI-generated code (see the human-in-the-loop section).

For every incremental step, conduct manual review of the AI-generated code and verify adherence to coding standards and style guides. _Manually_ test AI-generated code, and then run automated tests and static analysis tools, before committing the changes.

Do not rely on AI-generated tests to verify the correctness of the AI-generated code. Do not allow AI agents to modify your existing test suite without your explicit prompt and oversight.

Taking a test-driven approach to AI-assisted development is RECOMMENDED where feasible. Write your own tests, and then ask the AI to implement the changes necessary to make the tests pass.

Prefer high-level tests such as end-to-end system tests and integration tests. This approach is more robust and supports AI-assisted refactoring better than unit tests alone.

== Retrospective phase

After implementing a new feature or fixing a bug, ask the AI to update its own knowledgebase of the changes. The purpose is to maintain context for future AI coding sessions.

AI agents – like humans – have a limited working memory and cannot reliably learn from experience across sessions unless their learning is explicitly documented. When an agent gets stuck, context matters greatly in finding a way forward. Thus, it helps if agents have access to a log of how past bugs were fixed and features implemented. This allows future instances of the agent to reference solutions without having to reinvent solutions from scratch every time.

Best practice is to have an "AGENTS.md" file in the root directory of your project, and link from it all the files that document context that the agent should have access to, including but not limited to:

* Solutions to problems the agent previously encountered.
* Technical decisions and their rationale.
* Patterns that work well for your project.
* Examples of correct implementations for common tasks.
