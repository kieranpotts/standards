= Beyond code generation

Code generation is the most visible application of AI to software development.
It is not the most valuable one. The greater return is in the work that
surrounds the code: the quality controls that decide how robust, reliable,
secure, and performant a system turns out to be.

Before AI, the only quality checks that could be automated were those reducible
to deterministic rules — static analysis, type checking, schema validation, and
the execution of behavioral tests. Everything else required inference: judging
whether an abstraction earns its keep, noticing that a design document no longer
describes the system it documents, spotting that a change has widened the attack
surface, asking whether a specification actually describes what the customer
needs. These checks turn on judgment, opinion, and knowledge of context, so
until recently only humans could perform them. And because humans are expensive,
they were performed rarely — at a design review, a pre-release threat modeling
workshop, an annual audit — if at all.

Frontier models, given good guides, do a lot of this work well. That changes the
economics. Inferential checks that were affordable only occasionally can now run
on every change. Agents can be configured to:

* *Review code changes* against the project's standards, conventions, and
architectural intent — not merely against its linting rules.

* *Run threat modeling workshops* on a far more regular cadence than a
human-only team can sustain.

* *Detect drift* between the evolving implementation and the architecture and
design documents, keeping the architectural artifacts synchronized with reality.

* *Interrogate requirements* for ambiguity, unstated assumptions, and missing
acceptance criteria, before any code is written.

* *Propose architectures* from requirements specifications, with the options
considered and the trade-offs between them made explicit.

* *Decompose designs* into small, incremental units of delivery, feeding
backlogs and supporting continuous integration.

* *Audit a codebase* for structural drift — shallow abstractions, tangled
dependencies, repeated patterns — and report a prioritized set of remedies.

* *Triage incoming issues*, reproducing reported defects and classifying them
ahead of human review.

* *Validate delivered software against users' actual needs*, rather than only
against the acceptance criteria agreed up front.

The same constraint applies to all of it. An inferential check produces
findings, not decisions: a set of candidate problems for a human to accept,
reject, or defer. Its value is in coverage and cadence, not in its verdict.
Findings from inferential checks MUST NOT be treated as gates that pass or fail
a change on their own, and they MUST NOT displace deterministic checks, because
their judgment is itself probabilistic — two runs over the same input may not
agree. Use them to widen the net; keep deterministic checks for anything
mechanically checkable. The section on agentic workflows covers how the two
kinds of check combine as sensors in an agent harness.

Delegating quality control to agents therefore does not reduce the need for
human judgment. It relocates it — from performing every check to deciding which
findings matter.
