= Definitions

In this technical standard the following words and phrases have the following
meanings:

* A *model* is a large-language model (LLM), which is a type of neural network.
  It is the "brain" in an AI toolchain. Examples include Anthropic's Claude,
  OpenAI's GPT, Google's Gemini, and Z.ai's GLM. A model only consumes tokens
  (decoded from text or images) and outputs tokens (encoded into text or images),
  and has no inherent ability to act on computer systems — for that, you need a
  harness.

* A *model runtime* is the software and infrastructure layer that actually
  executes a model's inference calls — loading model weights, scheduling GPU/TPU
  compute, batching concurrent requests, and applying serving-time optimizations
  such as quantization or key-value caching. Examples include vLLM, llama.cpp,
  TensorRT-LLM, and Ollama's local engine.

* An *agent harness*, previously known as a scaffold, is a conventional computer
  program that wraps a model runtime. It mediates between the user, a model, and
  the rest of the computer environment. It can be thought of as a front-end user
  interface to models — most users will interact with models indirectly via an
  agent harness. Examples include Claude Code, Codex, OpenCode, and Pi. The agent
  harness constructs the system prompt, defines and executes tools from the wider
  environment (file reads and writes, shell commands, MCP server calls, etc.), and
  feeds the output from tool invocation back to the model as context. The agent
  harness also implements security, such as sandboxing the model's environment and
  managing permissions for tool access. Agent harnesses will proactively manage
  the model's context window (eg. through compaction of the current context before
  it is loaded back into the model on the next inference call in the loop) and
  things like task lists.

* An *agent* is an instance of a model (or multiple models) running in an agent
  harness in an iterative loop (ie. agent = model + harness). The underlying model
  proposes an action, the harness executes it via tool calls, and the result goes
  back into the model's context via the next inference call in the loop. This is
  repeated until the task is done or a stop condition is reached. A *coding agent*
  is just an agent that uses models trained specifically for computer programming
  tasks, running in an agent harness that is designed for integration into
  software development and operations workflows.

* A *tool* is a function that an agent harness exposes to a model and invokes on
  the model's request (known as a *tool call*). Examples include file edits,
  Bash/shell executions, web requests, and HTTP API calls. It is via tools,
  managed by the harnesses, that models touch real systems beyond their context
  window. *MCP (Model Context Protocol)* is the emerging industry standard
  protocol for serving tools or data to a harness.

* An *agent framework/SDK* is a library for building your own agent harness,
  rather than a finished product. Examples include LangGraph and the Claude Agent
  SDK. The Pi coding agent is a minimal agent harness that can be used
  out-of-the-box, but it is also a baseline framework designed for extensibility
  into custom harnesses.

* An *orchestrator* is whoever or whatever sequences the steps of an agentic
  workflow — deciding which step runs when, wiring the output of one step into
  the input of the next, and injecting verification gates between steps. An
  orchestrator may be a human invoking each step manually, a deterministic
  script, or an agent coordinating other agents. Orchestrators operate above
  the layer of the harness. In the case of multi-agent systems, the orchestrating
  agent is also known as a *supervisor agent*, which is capable of spawning and
  managing multiple *sub-agents* to complete tasks. Supervisor agents will use
  tools like Git worktrees to keep the work of each agent independent of the
  others on the same filesystem. Claude Squad, Crystal, and mux are examples of
  multi-agent systems. Some agent harnesses also have sub-agent orchestration
  capabilities.

* An *inference provider* is an organization that hosts and serves models via
  web services. This may be self-hosted infrastructure, a cloud service provider,
  or a third-party vendor API. The inference provider is distinct from the
  *model vendor*, though often they are the same company (eg. in the case of
  Anthropic's and OpenAI's closed systems). Inference providers such as
  OpenRouter and Ollama Cloud serve models from third-party vendors.

* *Context* is a model's "memory". It consists of a set of tokens (instructions,
  files, conversation, tool results) that's made available to the model in a
  single inference call. The *system prompt* is the initial set of instructions
  injected into a model's context windows by the harness. Typically, the system
  prompt is hard-coded into the harness and is not authored directly by the end
  user. Other sources of context that can be fed into a model session include
  skills, rules, and instructions files read from the environment, and direct
  input prompts from a human user. Different models have different capabilities in
  terms of how many tokens — ie. how much context — they can consume in a single
  inference call, which is known as their **context window**.

* Context is the main supply-chain/injection surface for agentic workflows.
  *Prompt injection* is adversarial instructions embedded in data the agent
  processes (files, web pages, tool results) that attempt to override the user's
  intended instructions. *Data exfiltration* is the transmission of sensitive
  material from an agent's context or its accessible environment to an
  unauthorized destination, whether via tool calls or model output.

* An agent *session* is a single continuous run of an agent, from the initial
  trigger through to the point where the task is done or a stop condition is
  reached. It spans every iteration of the agent's loop over that period —
  potentially many inference calls and tool calls — as a single unit of work.
  A session is the scope within which an agent's context evolves. Starting a
  new session begins with a fresh context window.

* Agent harnesses may record the full *transcript* of an agent *session*, eg.
  for auditability purposes. A session transcript would include the full sequence
  of user inputs, model outputs, and tool calls. This is distinct from the model's
  context, which is mutable during a session.
