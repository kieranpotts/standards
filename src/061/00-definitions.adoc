= Definitions

In this technical standard, the following words and phrases have the following
meanings:

* A *model* is a large-language model (LLM), which is a type of neural network.
  It is the "brain" in an AI toolchain. Examples include Anthropic's Claude,
  OpenAI's GPT, Google's Gemini, and Z.ai's GLM. A model consumes tokens (encoded
  from text or images) and emits tokens (decoded into text or images). It has no
  inherent ability to act on computer systems. For that, it needs a harness.

* A *model runtime* is the software and infrastructure layer that executes a
  model's inference calls. It loads model weights, schedules GPU/TPU compute,
  batches concurrent requests, and applies serving-time optimizations such as
  quantization and key-value caching. Examples include vLLM, llama.cpp,
  TensorRT-LLM, and Ollama's local engine.

* An *agent harness*, previously known as a scaffold, is a conventional computer
  program that wraps a model runtime. It mediates between the user, a model, and
  the rest of the computer environment. Think of it as a front-end to a model —
  most users interact with models indirectly, through a harness. Examples include
  Claude Code, Codex, OpenCode, and Pi. A harness constructs the system prompt,
  defines and executes tools from the wider environment (file reads and writes,
  shell commands, MCP server calls, and so on), and feeds the results of those
  tools back to the model as context. It also implements security, sandboxing the
  model's environment and managing permissions for tool access. And it
  proactively manages the model's context window — compacting the context before
  the next inference call, for example — along with things like task lists.

* An *agent* is an instance of a model (or several models) running in an agent
  harness in an iterative loop. In short: agent = model + harness. The model
  proposes an action, the harness executes it via a tool call, and the result
  goes back into the model's context on the next pass of the loop. This repeats
  until the task is done or a stop condition is reached. A *coding agent* is an
  agent that uses models trained specifically for computer programming tasks,
  running in a harness designed for software development and operations
  workflows.

* The *agent loop* is the iterative cycle an agent runs to pursue a goal rather
  than answer in a single pass. On each turn, the model observes its context —
  the goal, plus the results of anything done so far — decides on the next step,
  and requests an action; the harness executes that action as a tool call and
  feeds the result back into the context for the next turn. The loop repeats
  until the model judges the task done or a stop condition is reached, such as a
  maximum number of steps or a token budget. This cycle of acting, observing the
  result, and adjusting is what separates an agent from a single
  request-and-response exchange — it is what lets a coding agent write code, run
  the tests, read the failures, and try again. One unbroken run of the loop is a
  session.

* A *tool* is a function that an agent harness exposes to a model and invokes on
  the model's request (known as a *tool call*). Examples include file edits,
  Bash/shell executions, web requests, and HTTP API calls. Tools are how models
  touch real systems beyond their context window. *MCP (Model Context Protocol)*
  is the emerging industry standard protocol for serving tools and data to a
  harness.

* An *agent framework/SDK* is a library for building your own agent harness,
  rather than a finished product. Examples include LangGraph and the Claude Agent
  SDK. The Pi coding agent is both: a minimal harness that can be used
  out-of-the-box, and a baseline framework designed for extension into custom
  harnesses.

* An *orchestrator* is whoever or whatever sequences the steps of an agentic
  workflow. It decides which step runs when, wires the output of one step into
  the input of the next, and injects verification gates between steps. An
  orchestrator may be a human invoking each step manually, a deterministic
  script, or an agent coordinating other agents. Orchestrators operate above the
  layer of the harness. In multi-agent systems, the orchestrating agent is known
  as a *supervisor agent*. It spawns and manages *sub-agents* to complete tasks,
  and uses tools like Git worktrees to keep each agent's work independent of the
  others on the same filesystem. Claude Squad, Crystal, and mux are examples of
  multi-agent systems. Some agent harnesses have sub-agent orchestration
  capabilities of their own, so the boundary between harness and orchestrator is
  one of responsibility rather than packaging.

* An *inference provider* is an organization that hosts and serves models via
  web services. This may be self-hosted infrastructure, a cloud service provider,
  or a third-party vendor API. The inference provider is distinct from the
  *model vendor*, though often they are the same company — as in the case of
  Anthropic's and OpenAI's closed systems. Inference providers such as OpenRouter
  and Ollama Cloud serve models from third-party vendors.

* *Context* is a model's "memory". It is the set of tokens — instructions,
  files, conversation, tool results — made available to the model in a single
  inference call. The *system prompt* is the initial set of instructions injected
  into the context by the harness. It is typically hard-coded into the harness,
  rather than authored by the end user. Other sources of context include skills,
  rules, and instructions files read from the environment, plus the prompts a
  human types directly. A model's *context window* is the number of tokens it can
  consume in a single inference call, and this varies from model to model.

* Context is the main supply-chain and injection surface for agentic workflows.
  *Prompt injection* is adversarial instructions embedded in data the agent
  processes — files, web pages, tool results — that attempt to override the user's
  intended instructions. *Data exfiltration* is the transmission of sensitive
  material from an agent's context or its accessible environment to an
  unauthorized destination, whether via tool calls or model output.

* An agent *session* is a single continuous run of an agent, from the initial
  trigger through to the point where the task is done or a stop condition is
  reached. It spans every iteration of the agent's loop over that period —
  potentially many inference calls and tool calls — as a single unit of work.
  A session is the scope within which an agent's context evolves. A new session
  starts with a fresh context window.

* A *transcript* is the record of a session that an agent harness may keep, for
  auditability purposes. It includes the full sequence of user inputs, model
  outputs, and tool calls. A transcript is distinct from the model's context,
  which is mutable during a session.
